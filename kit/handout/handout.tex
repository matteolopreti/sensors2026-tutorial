{\LARGE\bfseries\color{ink} One loop, five versions}\\[1pt]
{\small IEEE SENSORS 2026 tutorial, Sunday 25 October: From Na\"ive Loops to FAIR Datasheets}

One simulated soft sensor, one indentation staircase, one acquisition loop. Each version fixes the bug the previous one left behind.

\hsec{What the five versions taught}
\renewcommand{\arraystretch}{1.12}
\begin{tabularx}{\linewidth}{@{}>{\bfseries}l >{\raggedright\arraybackslash}p{4.3cm} >{\raggedright\arraybackslash}X@{}}
\toprule
 & Loop & What it taught \\
\midrule
V0 & Blocking move, then sleep & Nothing is logged during ramps and holds. \\
V1 & Non-blocking polling & Coverage is fixed. Disk stalls give jitter (p99 about 60 ms). \\
V2 & Threads and a first-in, first-out queue & Jitter is fixed. Rows are stamped when read, so they lag the true time by 13.5 to 21.5 ms. At an unlucky start phase it loses about a third of the frames, and its log cannot show it. \\
V3 & Stamp at frame time, add a sequence number & Lag drops to about 0. The loss is now visible in the log. \\
V4 & Coordinator tick at 2$\times$ the frame rate & Loss is 0\,\% at every start phase in the frozen run (an earlier run lost up to 1.2\,\%, so timing still matters), and every lost frame shows in the log. \\
\bottomrule
\end{tabularx}

Whatever the testing path does not record, no analysis can recover. A test that passes is not the claim made true.

\hsec{Run the demo yourself}
\textbf{On your laptop.} Get the repo (\qr). In the folder that holds \texttt{naive\_vs\_threaded.py}, run:

\begin{center}\texttt{uv run --with numpy --with matplotlib python naive\_vs\_threaded.py --fast --seed 2}\end{center}

\texttt{--fast} runs a shorter staircase than the full-length run on the slides. Add \texttt{--phase-sweep} to see the loss at start offsets from 0 to 18 ms.

\textbf{In Colab.} Open the notebook (\qr) and run its cells in order. You need no install.

\hsec{Why your numbers will differ from the slides}
\begin{itemize}
\item The sensor and the disk are simulated. The disk-stall model is an assumption, so the jitter figures show the shape of the problem, not your disk.
\item Laptop, operating system and system timer change when threads wake up, so the same code gives different jitter and different loss.
\item The start phase matters most. The loss in V2 ranges from 0 to 34.1\,\% as the start offset moves from 0 to 18 ms. Press Start a few milliseconds later and you get a different datasheet.
\item The slides show the full-length run. \texttt{--fast} is shorter, so its numbers carry more edge effects.
\end{itemize}
Compare V2 and V4 on your own machine, then write your two loss figures below.
