# One acquisition loop, five versions: same sensor, different datasheet

One simulated soft sensor, one indentation protocol (staircase 0 -> 3 mm -> 0 in `--fast`, 0 -> 4 mm in
0.5 mm steps by default; 2 mm/s ramps; 2 s dwell per step), and the loop that records it in five versions
(`loops.py`), each fixing the previous version's bug:

| version | loop | fixes | measured bug it still has (full length, seed 2, phase 4 ms; frozen) |
|---|---|---|---|
| V0 | AIS SI Listing 1: blocking `move_to`, `sleep(2.0)`, one read pair per step | - | no ramp or dwell data (16 samples), relaxation and hysteresis n/a, full-scale force -10% (4.14 vs 4.59 N), 99% of frames lost |
| V1 | one thread, non-blocking stage, reads every 20 ms tick, synchronous disk | coverage | dt p99 61 ms / max 68 ms (disk stalls, see below), lag -10.5 ms, 9% of frames lost |
| V2 | V1 + threads only: pollers at native rates (no averaging), latest-value registers, coordinator, FIFO -> logger | jitter (p99 24–29 ms) | rows stamped on read: sensor-force lag +18 ms (phase-dependent, 14-20.5 ms over the sweep); loses 35% of frames at the pinned phase (0-38% over the sweep), and the log cannot show it (n/a: no frame time or seq) |
| V3 | V2 with rows stamped at the sensor frame time | lag (~0 ms) | 50 Hz tick on a 50 Hz register drops frames at unlucky phase: 35% lost at the pinned phase (0-35% over the sweep); visible loss = true loss (frame time + seq) |
| V4 | V3 with the coordinator tick at 100 Hz (2x frame rate) | lost frames | 0% at the pinned phase, at most 1.2% over the 0-18 ms sweep, every lost frame visible; fails no check |

**Sign convention:** lag = sensor-minus-force timestamp error; positive = the sensor channel is older than the force channel.

**Frame loss: true vs visible.** The simulator numbers every frame it produces, so `frames_lost_true_pct` (produced
frames never logged) exists for every version. `frames_lost_visible_pct` uses only logged columns: V0-V2 log no frame
time or seq (rows are tick-stamped; a missed frame is just a repeated stale value), so it is `n/a`; V3/V4 log the frame
time and a `seq` column, so gaps are visible. Checks use the true loss. Stage line: V2 loses frames and its log cannot show it.

**Start-phase dependence (V2, V3).** Sensor frames arrive at n x 20 ms + 4 ms; the 50 Hz coordinator tick falls on
`--phase-ms` + n x 20 ms. Both clocks are exactly 50 Hz, so what is lost is set by the offset, not by a beat, and by
host wake-up jitter (the sensor thread wakes a few ms after a frame arrives; a low-jitter host such as Colab may lose less
at a given phase). `--phase-ms` (default 4, pinned in `loops.PHASE_MS`: tick coincides with frame arrival, where loss peaks)
is printed in the table header. `--phase-sweep` runs `--sweep-versions` (default V2,V3) at 0..18 ms (`--fast`: 2 steps,
~50 s per version) and prints true loss, visible loss and lag per phase. Numbers are host-dependent; `--fast` sweeps carry
~1-2 pp of edge-frame loss. V2 lag also moves with phase. Same code, different start, different datasheet.
V4 ticks at 100 Hz: at most 1.2 % lost over the 0–18 ms sweep, and every lost frame is visible in its log.

Physics: standard linear solid sample (k_inf = k1 = 1 N/mm, tau = 1.5 s, probe cannot pull); sensor
output `0.5F - 0.02F^2` V through a 50 ms first-order lag; 20 ms frames, 4 ms latency; noise
0.02 N / 5 mV. **Assumption, not a measurement:** 5% of disk writes stall 20-40 ms (`Disk`, `p_stall`, `stall_s`);
V1 jitter comes from these stalls (the serial read is paced by the frame clock; `--no-stalls` removes them: V1 dt p99 28 ms on one `--fast --seed 1` run, still above V2's 24 ms). Ground truth is the simulator's noiseless 1 kHz trace,
run through the same `metrics.datasheet` as every log. `n/a` = not measurable from that log.

```bash
uv run --with numpy --with matplotlib python naive_vs_threaded.py --fast --seed 1     # ~76 s
uv run --with numpy --with matplotlib python naive_vs_threaded.py --versions V0,V3    # pick versions
uv run --with numpy --with matplotlib --with pytest python -m pytest -q test_demo.py  # ~150 s
```

Colab: open `kit/demo_colab.ipynb` (generated by `kit/build_notebook.py`; no uploads). Other options: `--seed`,
`--phase-ms`, `--phase-sweep`, `--sweep-versions`, `--no-stalls`, `--velocity`, `--dwell`, `--tau-relax`, `--tau-sensor`.

Outputs in `out/`: `timeline` (one panel per version), `loops` (sensor vs force), `datasheet` (table
with a "bug exposed" row), SVG + PDF, plus one CSV log per version. `metrics.failures` names the
checks a log fails against truth; `test_demo.py` checks that they flag V0, V1, V2 and a planted defect
(V3 with no logging during the dwell); for V1-V4 it asserts that the previous version's bug metric is gone and
the version's own is present (V3 loses frames at the pinned phase, seeds 1-3, and none at +10 ms; V4 none at either; V2's true loss is >5% with no visible loss; V3's visible loss matches its true loss within 2 pp).

Hysteresis and sensitivity differences between V1-V3 are small next to the seed-to-seed spread
(up to ~0.5 pp hysteresis): quote coverage, relaxation, full-scale force, jitter and lag first.

**Frame loss counts only frames produced while logging ran**: each loop records `rig.t_stop` when logging stops, and
`frames_lost_true_pct` is relative to the frames produced up to it (threaded versions: one full coordinator tick before the last completed tick, so a frame landing on the last tick is not counted). **Hysteresis is not a check** (noise-level: 0.6–1.4 %
across seeds 1-3, full length, against truth 0.97 %); it stays in the table and is `n/a` when a step has < 10 samples
(V0). `--out DIR` writes logs and plots to DIR (default `out/`).

Full-length numbers (seeds 1–3, pinned phase 4 ms, and the 0–18 ms sweep): `out/freeze/NUMBERS.md`, generated by `python freeze_numbers.py` from the frozen runs. Quote numbers only from that file.
